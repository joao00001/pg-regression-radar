    PostgreSQL on Kubernetes

    pg-regression-radar¶

    Detects PostgreSQL query performance regressions and pinpoints which Kubernetes deployment caused them.

    Get started How it works

    Example alertRegression
    QuerySELECT * FROM orders WHERE customer_id = $1
    Latency4.1 ms → 38.6 ms×9.4
    Deploycheckout-api · revision=v2
    Confidence0.97

    Illustrative values.

    The problem¶

    Teams running Postgres on Kubernetes (CloudNativePG, Zalando, Crunchy, Percona...) deploy applications many times a day via GitOps (ArgoCD, Flux, Argo Rollouts). When query latency spikes, the first question in every post-mortem is:

    Which deploy caused this?

    Today that question is answered manually: open Grafana, look at pg_stat_statements, try to recall when the last deploy happened, cross-reference timestamps by eye. No open-source tool closes that loop automatically.

    pg-regression-radar does.

    How it works¶

    1 Collector

    Scrapes pg_stat_statements on an interval and keeps a bounded in-memory time series per queryid.

    Architecture Overview Collector Internals

    2 Deploy Event Ingester

    Receives webhooks from ArgoCD, Argo Rollouts, and Flux and stores normalised DeployEvent records.

    Deploy Sources & Webhooks

    3 Correlation Engine

    Runs a real two-stage detection for every deploy event: E-divisive change-point location, then Welch's t-test confirmation.

    Detection Algorithm

    4 Alerting

    Fires a Slack-compatible webhook with the query text, latency before/after, change factor, and confidence score.
