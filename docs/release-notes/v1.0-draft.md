# v1.0 release notes — working draft

*Status: draft, for the project owner to decide the exact version number
against. Not published anywhere, not linked from the docs site nav or
`mkdocs.yml`. Delete or move into `docs/` proper once a version number is
picked (this document deliberately doesn't assume it'll be called "v1.0" —
see [`docs/roadmap.md`](../roadmap.md#version-roadmap): that name is likely
but not yet decided).*

This covers every commit merged to `main` between `v0.1.0` and now (see
[`CHANGELOG.md`](https://github.com/joao00001/pg-regression-radar/blob/main/CHANGELOG.md)
for the full, categorized list with commit links), plus two branches not yet merged that this release depends
on: `ci/release-publishing` (adds `release.yml` itself — without it there's
no way to actually cut and publish a tagged release) and
`feat/release-notes-automation` (this document, `CHANGELOG.md`, and the
automation that generates future release notes), stacked in that order.

Known gaps and what's intentionally out of scope for this release are
tracked in one place, [`docs/roadmap.md`](../roadmap.md) — see "Known
robustness gaps" and "Operational follow-ups" there rather than duplicating
that list here.

## What this release delivers

**Detection & correlation improvements:**

- Regression findings are now deduplicated across a `queryid` rotation.
  Previously, a query whose `queryid` changed mid-analysis-window (a normal
  PostgreSQL behavior on planner-relevant schema changes) could be reported
  as two separate regressions instead of one continuing one.
- Plan-diff correlation: the correlation engine can now capture and diff a
  query's execution plan around a detected regression, from either of two
  sources — `EXPLAIN (FORMAT JSON, GENERIC_PLAN)` (PostgreSQL 16+, an
  estimate) or, when available, `pg_store_plans` (the real, previously
  executed plan — preferred when present).
- `cmd/manager` now backfills its in-memory detection state from the
  Postgres persistence backend on restart, instead of starting cold.

**Multi-cluster (fleet) support:**

- A `PostgresWatch` can now point at a Postgres cluster running in a
  *different* Kubernetes cluster than the manager itself
  (`spec.remoteClusterSecretRef`, a kubeconfig Secret in the hub cluster).
  Previously this required manually copying the DSN Secret between
  clusters by hand.

**Security:**

- The ingester's webhook endpoint now requires an `X-Webhook-Token` bearer
  token. Previously any network path that could reach the ingester could
  post a fabricated deploy-event webhook with no authentication check at
  all.

**Performance:**

- Six separate performance changes reduce algorithmic complexity or
  allocation pressure across the collector, ingester, and correlation
  engine's hot paths (E-Divisive O(n³)→O(n²), several O(N)/O(N×M) poll and
  scan loops replaced with cursor-based or O(1) equivalents, reduced lock
  contention in `Engine.Analyse`, and slice pre-allocation to cut GC
  pressure). None of these change behavior — they're the same detection
  logic running measurably faster/lighter under load.

**CLI & developer experience:**

- A single unified `pg-regression-radar` CLI binary now wraps all
  subcommands, so `go install` sets up everything from one target instead
  of four.
- `--version` and `--dry-run` flags were added across all four binaries.

**CI/CD & quality:**

- A real `kind` + CloudNativePG e2e workflow validates `cmd/manager`'s CRD
  mode against an actual Kubernetes cluster and Postgres operator
  (`e2e-kind.yml`).
- A documented, CI-enforced PostgreSQL 16/17/18 + EDB Postgres Advanced/
  Extended Server support matrix.
- Expanded e2e coverage against a real PostgreSQL instance for the features
  above.
- Tagged releases publish five container images and a Helm chart to GHCR,
  Trivy-scanned, SBOM-attested, and cosign-signed.
- Every tagged release gets auto-generated, categorized release notes as a
  real GitHub Release, and the full history back to `v0.1.0` is captured in
  `CHANGELOG.md`.

**Documentation:** a full MkDocs Material documentation site was stood up
(previously just a `README.md`), covering architecture, the detection
algorithm, configuration, installation, multi-cluster mode, the support
matrix, API/CRD versioning policy, and the roadmap — see
[`docs/index.md`](../index.md).
